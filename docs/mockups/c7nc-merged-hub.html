C7NC — one section for everything that connects

Everything that connects C7NTAX to something else is already here; it is filed under three different ideas of what it is. CloudConnect is a 79 KB page of five tabs sitting under Administration, which is where settings live — but a connector is not a setting, it is a relationship. C7NC is a two-item group for companion clients, and one of its two items is a payment service whose connection is configured in the other section, which is why that page's first button is a link back to CloudConnect. This mockup folds them into one top-level section, C7NC, with a landing page that answers "is anything broken?" before "which connectors exist", and a page of tabs per subject.

Today

Five tabs of one page behind one permission: Connected · Add a connector · Configuration · AI models · Email connectors. Reached from Administration, named after the thing it is not (a cloud).

Proposed

A hub, then four subjects with tabs of their own — and each subject shows only what the person opening it can actually use. CloudConnect retires as a name.

Nothing else moves

The connectors, the wizards, the sync logs, the M365 panel, the add-in installer and every API endpoint stay exactly as they are. This is a front door and a filing system, not a rewrite.

The name — renamed in

  • · apps/web/src — nav label, descriptions, page titles, empty states
  • · apps/api/src — the route file, log prefixes, user-facing error strings
  • · docs/API.md, docs/openapi.yaml (regenerated), docs/api-operations.json
  • · HelpDoc.tsx — 33 references, including the configuration walkthrough
  • · probes and the two guard scripts that name the page

The name — deliberately not rewritten

  • · BuildNotes.md, Retrace.md, PlanDocs/ — history is what happened, and rewriting it would make every past entry wrong
  • · apps/api/src/snapshots/ — captured audit-log text from a running instance
  • · the /api/cloudconnect alias itself, which must keep its old spelling to be an alias
  • · database rows — the audit log already records the page under its old name, and there is nothing to fix in history

A grep proves it either way: no occurrence of CloudConnect in apps/web/src or apps/api/src outside the alias, and a probe that the alias still answers.

The design choices, in the order they matter

1 · A hub, not a list

"Is anything broken?" is answered before "which connectors exist", because that is the question people arrive with. Status first, catalogue second.

2 · One name

C7NC survives; CloudConnect retires. Two names for one place is how a product ends up with a page nobody can describe.

3 · A subsection is a question

Services, Email, Models, Apps — four different questions. Tabs inside a subject are facets of one question (Connected / Available / Attention), not four more subjects.

4 · Show only what you can open

The hub lists the subsections your permissions allow, so nobody clicks into a 403. The API already works this way; the nav did not.

5 · A service gets a page

FlexPoint's connection, options, ledger and invoices are one service; four tabs of one page is the honest shape. It also removes the link back to where the connection is configured.

6 · Signposts, not moves

API Access and Alert webhooks stay in Administration and are linked from the hub. Moving a screen without moving its permission makes a hub half empty.

7 · Redirects, not breakage

Every old address answers, including the API alias. Nothing that was bookmarked, linked from Help, or called by an integration stops working.

8 · No new permissions

IntegrationView for reading, IntegrationManage for changing, InferenceView for models — exactly what the API already enforces. The nav stops asking for more than the page needs.
