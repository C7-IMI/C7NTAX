Mockup — nothing changed Developer — the modern interface only (useRedesign())

A section for the changes that are not normally available, that says what each one can destroy

The instance already carries a developer surface: pnpm db:sample-off empties the database and db:sample-on puts it back, ten seed packs re-fixture the instance, a snapshot poller rewrites the fixtures after every change, and eight guard commands and two generators stand between a mistake and main. All of it is a terminal, a README and a memory. Below, the same capabilities are given a face in the modern interface — with the blast radius stated on the control, in rows, before it acts.

Every figure was read from the running instance on 9 October 2026, and the dry run on the purge screen is the real arithmetic of WIPE_MODELS and KEEP_MODELS in apps/api/src/sample-data-toggle.ts. Where a figure could not be read it is absent rather than illustrated.

Reachable only with developer:manage — a permission this application does not have yet

Proposed as one value in the existing vocabulary (packages/shared/src/enums.ts), by the same reasoning as console:use: it decides whether the section is drawn at all, and every action behind it still runs an existing route under its own permission. Held by the Super Admin role — 4 of the instance's 17 accounts — today jason.redwine@cyber7group.com, jonathan.redwine@cyber7group.com, stephen.simmons@cyber7group.com, persona.superadmin@c7ntax.local. Everyone else sees no section, no rail entry and no route.

can("developer:manage") 4 accounts
Every action here is written down before it can be questioned, including the reads: actor, IP, the section and the operation, the reason, and what the dry run said the blast radius was. The reason is mandatory for the destructive ones and the button stays disabled without it. The record is written to the audit log by the service that performs the work, not by the screen — a section whose logging lived in the browser would be one a curl could skip. On the current instance the audit log holds 4,919 rows, and the purge deletes it with the rest of the business data, so the purge's own receipt is written outside it — see the note on the purge screen.
Screen one — Developer hub · the proposal

Every developer capability, in one list, each row answering the same three questions

Grouped by subject rather than by script: data and the database, the environment, what talks to the outside, who can act, what watches the instance, and the four things nothing can undo. Each entry carries where it lives today, so the section can be read as a map of what already exists rather than a wish list.

The rule this screen is built on: the answer to "can destroy" is a countable sentence, not a colour. Where the count is not known, the control cannot arm. That is why the purge screen next door leads with 8,085 rows across 85 tables rather than a red button, and why the entries below that destroy nothing say so in the same place, in the same words.
What the section holds
Where this lives today

A terminal and a README. 2 toggles, 10 seed packs, 8 guard commands and 2 generators — and exactly two of these capabilities have a screen: Administration → Security (sessions) and Administration → API access (keys). The rest is a command somebody has to remember.

Nothing above is a new capability except where it says so. The section's whole claim is that the capability already exists and is currently unusable by anyone who did not write it.

The honest fix is a decision, not a patch: either those four models join WIPE_MODELS, or they join KEEP_MODELS with a sentence saying why a client list is identity. Both are one-line changes to the file that already makes the decision — which is the argument for showing the third list rather than quietly extending the second.

The screen does not resolve it. It counts it, names it, and puts it next to the preserved list, so that the person pressing the button is deciding about the instance they actually have.

Four operations, none of them reversible, each one showing the sentence it will be judged by
